- 解説リーダーの検索入力とクリアボタンを独立した操作要素として整理し、クリア後の一覧復帰をブラウザテストで確認。
- スマホメニューの閉じる操作で開くボタンへフォーカスを戻し、チュートリアルへ移る際もメニューを閉じる。メニュー経由の章内移動ではスクロール先を保つ。
- 解説リーダーを独立画面として分割読み込みし、肥大化したメイン画面の責務を整理。検索・絞り込み状態は画面を閉じても保持する。見た目や問題データは変更していない。
- 解説リーダーは最初の20件を一覧表示し、選んだ1件だけ答え・解説・図解・出典を開く方式へ変更。残りは20件ずつ表示でき、検索や絞り込み時は一覧を先頭へ戻す。進捗画面のデータ管理も折りたたみ、日常の学習状況とバックアップ操作を分離。
- 「読んでから解く」をランダム10問の問題直前表示から、分野選択→5つの要点を読む→同じ5問で確認する独立した導線へ変更。旧セッションの再開形式は維持し、新導線の途中再開、9分野の問題選択、アクセシビリティを検査した。
- 初回の学び方を2段階の専用チュートリアルへ分離。完了後は18問の全体像モードか学習メニューへ進み、再訪時はメニューを直接表示する。トップページに重複していた説明を外し、メニューから再表示可能にした。
- スマホの小さなプルダウンを、背景オーバーレイ付きのスライド式メニューへ変更。開くボタンも左に置き、左から出る動きと揃えた。学習と記録を分け、各導線に短い説明を付けた。Escape・背景・閉じるボタンで閉じられ、メニューだけを分割読み込みして初期表示の容量上限を維持。

## 検証と公開

型・lint・format・単体テスト・文書リンク・型カバレッジ・本番ビルド・bundle上限は `npm run check` で検査します。Chromiumの導線・アクセシビリティ検査は `npm run test:e2e`、PWAは `npm run test:pwa`、表示品質は `npm run lighthouse:check` で確認します。mainへのpush後はGitHub Actionsの品質ゲートに成功した変更だけをGitHub Pagesへ公開します。詳しくは[品質運用](QUALITY_OPERATIONS.md)と[開発ガイド](DEVELOPMENT.md)を参照してください。
